# 机制分析：Z8 快门音子系统

> 所有地址都是 **EG 模块的虚拟地址**，模块基址 `0x40160000`。
> 对应文件偏移 = VA − `0x40160000`（EG 模块内部）。
> 分析基于 Z8 固件 **C 3.11**（EG 长度 81,807,709 字节）。

---

## 1. 内存布局

```
0x43FB6000 – 0x43FB7A88   描述符区(整数表 / vtable / 字符串)
0x43FB7A88 – 0x43FB8000   三张跳转表
0x43FB8000 – 0x44009480   PCM 音源库           ← 音频数据
0x44009480 – 0x44025300   资源索引区(指向 0x44026xxx/0x44043xxx)
```

音源库里没有文件名、没有 RIFF 头、没有路径字符串——**就是裸 PCM**。
这导致按"资源文件/字符串"的思路搜索全部落空。

---

## 2. kind 体系

固件用 **kind**（1..26）索引音频资源，由三张跳转表分派：

| 表 | 表地址 | 分发器 | 内容 |
|---|---|---|---|
| 地址表 | `0x43FB7DA0` | `0x40E3469C` | kind → 返回 RAM 缓冲区地址 |
| 长度表 | `0x43FB7E70` | `0x40E348F4` | kind → 返回字节长度（默认 9600） |
| 音量表 | `0x43FB7F40` | `0x40E349F8` | kind → 返回百分比 |

表项格式：8 字节指针，索引 `(kind − 1) × 8`。

### 分发器代码

```asm
0x40E3469C  sub  w8, w0, #1        ; 地址分发器入口，w0 = kind
0x40E346A0  cmp  w8, #0x19
0x40E346A4  b.hi default
0x40E346A8  mov  x9, #0x43FB7DA0
0x40E346B8  ldr  x8, [x9, x8, lsl #3]
0x40E346BC  br   x8
```

```asm
0x40E348F4  mov  w8, w0            ; 长度分发器入口，w0 = kind
0x40E348F8  mov  w0, #0x2580       ; 默认 9600
0x40E348FC  sub  w8, w8, #1
0x40E34900  cmp  w8, #0x19
0x40E34904  b.hi 0x40E34934
0x40E34908  mov  x9, #0x43FB7E70
0x40E34918  ldr  x8, [x9, x8, lsl #3]
0x40E3491C  br   x8
```

## 3. 五个类型的分派

从长度跳转表实际内容解出：

| kind | 长度 getter | 返回字节 | 时长 |
|---|---|---|---|
| 10, 14, 18, 22 | `0x40E34920` | 28800 | 150 ms |
| 11, 15, 19, 23 | `0x40E34934`（默认路径） | 9600 | 50 ms |
| 12, 16, 20, 24 | `0x40E34928` | 19200 | 100 ms |
| 13, 17, 21, 25 | `0x40E34930` | 7680 | 40 ms |
| 1..9, 26 | 各自 | 4800 / 其它 | 25 ms 等 |

换算：**192 字节/毫秒**（48 kHz × 2 声道 × 2 字节）。

### 地址 getter（直接返回固定 RAM 地址）

| kind | 函数 | 返回 |
|---|---|---|
| 14 | `0x40E347F0` | `0x0A15C2B100` |
| 15 | `0x40E34804` | `0x0A15C32180` (= +28800) |
| 16 | `0x40E34818` | `0x0A15C34700` (= +38400) |
| 17 | `0x40E3482C` | `0x0A15C39200` (= +57600) |

## 4. 初始化复制（ROM → RAM）

`0x40E342E8` 起有 18 条 `bl 0x40CA9AA0`，形态：

```
x1 = 0x0A15C1xxxx   (RAM 目标)
x2 = 0x43FBxxxx     (ROM 源)
w3 = 长度
bl 0x40CA9AA0
```

C 型的 RAM 基址 = **`0x0A15C2B100`**，四个缓冲区依次连续排布，
总长度 65,280 字节——和 ROM 里的四个资源一一对应。

**关键结论**：由于 ROM 和 RAM 都连续，把"读多少"从 28800 改成 65280
就能一次读完整个 340 ms，**不需要改复制逻辑**。

## 5. 播放 API

### 入口

```asm
0x40E31A44  play(w0 = 声音ID, x1 = 完成回调)
    alloc(0x10) ; [x] = ID ; [x+8] = 回调
    alloc(0x18) ; [x] = 上者 ; [x+8] = 0x40E3159C
    w0 = 0x04100051 ; bl 0x40E32E6C
```

`0x40E32E6C` 是消息入队函数（分配 0x38 节点，投递到 `0x40C00BAC`）。

### 五个事件

| 事件码 | 投递函数 | 参数 |
|---|---|---|
| `0x04100051` | `0x40E31A44` | `play(id, callback)` |
| `0x04100052` | `0x40E31ADC` | 无参 |
| `0x04100053` | `0x40E31B38` | 无参 |
| `0x04100054` | `0x40E3205C` | `cmd(a, b)` |
| `0x04100055` | `0x40E319B8` | 四个参数 |

蜂鸣器（`0x40376E98`）就是调用 `play(0, callback)`。

## 6. 设置分发器

`0x40E31130` 不是播放器，而是**设置变更分发器**。它订阅了 5 个属性：

| 属性 ID | 含义 | 处理函数 |
|---|---|---|
| **`0x02006100`** | **快门音类型**（值被钳到 ≤5） | `0x40E31840` |
| `0x02001252` | 开关（布尔） | `0x40C80D4C` |
| `0x06001DD2` | 其他参数 | `0x40E32058` |
| `0x04004300` | 其他参数 | `0x40E32058` |
| `0x0000217C` | 通道使能 | 事件 `0x04100060` |

### RAM 状态块

```
0xA038FE9D0 – 0xA038FEA70
  +0x48  (0xA038FEA18)  当前快门音类型
  +0x58  (0xA038FEA28)  类型已生效标志
  +0x70  (0xA038FEA70)  消息队列指针
```

写 hook 时可以直接读 `0xA038FEA18` 拿到当前类型，比翻菜单可靠。

## 8. 播放窗口（实测）

用扫频/多音槽实验测得：

```
样本位置   0 ────── 150 ────── 300 ── 405 ms
播放窗口 A      [======]        约 48–184 ms
播放窗口 B               [======]  约 196–336 ms
```

两个窗口相差约 140–150 ms，长度约 135–150 ms。
另有一个**约 50 ms 的固定偏移**，成因未确认（见 open-questions）。

## 9. 慢门的两阶段

慢快门的声音由**两次快门事件**分别触发：

```
按下快门 ── 前帘(kind15) ──── 曝光时间 ──── 后帘(kind16/17)
```

- 1/30：前帘在 33 ms 被后帘打断，总长约 195 ms
- 2 秒：前帘完整播完 340 ms，后帘在 2 秒后再播 140 ms

固件里没有"前帘是否播完"的状态可用，所以无法只关闭长曝光的后帘。
