# 实验记录

从"完全不知道快门音在哪"到"能换任意音频"，一共刷了 **15 个固件版本**。
这里记录每一次的判断依据、结果和结论——包括走错的路。

> 机型：Nikon Z8，固件底板官方 **C 3.11**
> 所有验证都在真机上进行，通过手机录音 + FFT 分析判断实际播放内容。

---

## 阶段一：找音源（全部失败）

### 尝试 1：按文件名搜索

Z8 固件里有 `CaptureShutterSound.c`、`SS_START`、`AEAFCV`、`%s\%s%03d.bin` 等字符串，
看起来像是"读文件播音频"的服务。

**结果**：`0x4102D604` 等 5 个处理函数的调用者都是 **0 处**，
指向描述符表的 ADRP 也是 **0 处**。

后续在 04.23 里真的把 hook 打进那个模块并刷机测试——**完全没有声音变化**，
实机证明这段是**死代码**。

### 尝试 2：蜂鸣器

`0xA03223130` 有 4 个薄壳函数在写。反汇编发现它们是：

```
0x40D2BC8C  置位（读-改-写，w1 当掩码）
0x40D2BCC8  清位（mvn w1,w19）
0x40D2BD04  写单个位
```

**结论**：这是个位控制寄存器，只能"嘀"，做不出 5 种音色。排除。

### 尝试 3：音频引擎

`0xA032230E0/E4/E8` 的引用全部集中在 `0x40376094–0x40376444` 约 1 KB 代码里，
而这些函数**全部零调用者**。排除。

### 尝试 4：跨机型共享区块 ← **成功**

思路：Z8 和 Z9 都有 5 种快门音，**音源数据应该逐字节相同**。
扫描两块 EG 的相同区块（排除代码、排除全零）：

```
Z8 0x43FB8200 – 0x44003200   307,200 字节
```

特征：16-bit 平滑数据、左右声道平均差 1.02、**8 处静音间隙**。
导出成 WAV 试听——**确认是快门音和蜂鸣音**。

## 阶段二：搞清结构

### 04.25 扫频实验

把 `0x43FC9960` 起 405 ms 填满 **400→4000 Hz 线性扫频**，录音后测频率轨迹：

| 快门 | 起始频率 | 结束频率 |
|---|---|---|
| 1/30 | 824 Hz | 2022 Hz |
| 1/1000 | 2145 Hz | 3387 Hz |

反推播放位置：**48 ms → 184 ms** 和 **196 ms → 336 ms**，
两窗口相差 148 ms ≈ 一个槽。

### 04.26 三槽实验

三槽分别填 500 / 1000 / 1500 Hz。录音显示**跨槽切换**，确认槽边界。

### 阶段三：找到真实资源表 ← **转折点**

**S3**（[@s3lemming](https://github.com/s3lemming)，Z9 侧研究者）给出的关键提示：

> 不要按静音切段，要按「音色选择 → 资源编号(kind) → 源地址/长度 → 阶段分派」来追。
> 长度不是 `(offset,length)` 表，而是**跳表返回常量的代码**。

顺着提示找到**长度 getter 簇** `0x40E348F4` 和跳转表 `0x43FB7E70`，
进而找到初始化复制循环 `0x40E342E8`，得到完整的 18 条资源映射。

**这解释了之前的困惑**：先前认定的"405 ms 段"其实是
**B 的终段 + C 的全部 4 个资源 + 一部分 D**，边界完全错了。

## 关键教训

### 1. 长度字段是 u16、单位 4 字节

设成 0 → 底层算 `0 − 1` 回绕成 65535 单位 × 4 = **262,140 字节 = 1365 ms**，
开始读缓冲区之外的内存，播出垃圾。

**长度最小要给 4（1 单位）以上。**

### 2. 引擎长度上限

65,535 × 4 ≈ **1.37 秒**。S3（@s3lemming）在做 1.5 秒时因此必须拆成两块各 144,000 字节。

### 3. 参考：Z30 的最大长度

Z30 的项目用 8 kHz 单声道 WAV，×6 插值到 48 kHz 双声道：

```
17,280 字节源 → 207,360 字节 PCM = 1.08 秒
```

说明**音频输出通路本身能播 1 秒以上**，340 ms 远不是物理极限。

### 4. 播放不是"整段"

短曝光下前帘会被后帘事件打断；长曝光下前帘能完整播完，后帘变成多余尾巴。
**同一个后帘，两种行为**，固件没有状态可供区分。
